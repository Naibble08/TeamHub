# Инструкция администратора

Установка, настройка и запуск системы TeamHub (п. 9 ТЗ).

## 1. Требования

- Windows 10/11 или Windows Server (либо Linux/macOS для тестового стенда), не менее
  4 ГБ ОЗУ (не менее 16 ГБ — при использовании локальной LLM через Ollama);
- Node.js версии 18 LTS или новее;
- современный браузер на рабочих местах сотрудников (Chrome, Edge, Firefox).

## 2. Установка

**Windows, без командной строки.** Скопируйте папку TeamHub на сервер и запустите
`installers\server\install-server.bat` — мастер сам поставит Node.js (если его нет),
установит зависимости, включит автозапуск сервера при загрузке компьютера и откроет
нужный порт в брандмауэре. На каждое рабочее место сотрудника — `installers\client\install-client.bat`,
создаёт значок TeamHub на рабочем столе. Подробности и решение проблем —
[installers/README.md](../installers/README.md).

**Вручную (Windows/Linux/macOS):**

```bash
git clone <адрес репозитория> teamhub
cd teamhub
npm install
```

## 3. Настройка (config/config.json)

Файл `config/config.json` создаётся автоматически при первом запуске (копия
`config/config.example.json` со случайным `jwtSecret`). Он не входит в поставку исходного
кода и не должен передаваться третьим лицам (п. 4.6, 5.6.4 ТЗ) — в нём хранятся ключи
доступа к внешним сервисам.

Основные параметры:

| Параметр | Назначение |
|---|---|
| `port` | порт HTTP-сервера |
| `auth.jwtSecret` | секрет для подписи токенов авторизации (генерируется автоматически) |
| `auth.tokenExpiryDays` | срок действия токена авторизации, не более 30 суток |
| `uploads.maxSizeMB` | ограничение размера загружаемого документа (по умолчанию 50 МБ) |
| `llm.enabled` | единый параметр полного отключения функций ИИ (п. 5.6.5) |
| `llm.activeProvider` | `template` (без ИИ), `gemini` (облачный) или `ollama` (локальный) |
| `llm.timeoutMs` | тайм-аут одного обращения к LLM (по умолчанию 10000 мс, п. 5.6.6) |
| `llm.providers.gemini.apiKey` / `.model` | параметры облачного поставщика Google Gemini |
| `llm.providers.ollama.baseUrl` / `.model` | адрес и модель локального сервера Ollama |

Смена поставщика LLM выполняется изменением `llm.activeProvider` без изменения кода
(требует перезапуска сервера). Полный список и сравнение поставщиков — приложение А ТЗ.

## 4. Запуск

Если сервер разворачивался через `install-server.bat` — он уже запущен и настроен
на автозапуск, этот шаг можно пропустить. Иначе:

```bash
npm start
```

Сервер печатает в консоль адрес (`http://localhost:<port>`) и, при первом запуске,
логин и разовый пароль администратора. Смените пароль сразу после первого входа
(кнопка «Сменить пароль» в интерфейсе).

Для эксплуатации рекомендуется запускать процесс через диспетчер служб (например,
NSSM на Windows или systemd на Linux) с автоматическим перезапуском при сбое.

## 5. Резервное копирование

Все данные системы хранятся в:

- `data/teamhub.db` (и файлы `-wal`/`-shm` рядом с ним, режим WAL) — база данных;
- `uploads/` — файлы документооборота.

Регулярно (не реже раза в сутки, п. 4.4 ТЗ) копируйте оба каталога на резервный носитель,
предварительно остановив запись (или используйте `VACUUM INTO` / штатное резервное
копирование SQLite в режиме WAL, не требующее остановки сервера). Восстановление —
подмена файлов из резервной копии и перезапуск сервера.

## 6. Управление сотрудниками

Раздел «Сотрудники» доступен только администратору: создание, редактирование карточки
(имя, фамилия, логин, должность, дата рождения — день и месяц, роль) и деактивация
учётной записи. Деактивированный сотрудник не может войти в систему, но его задачи,
сообщения и документы сохраняются.

## 7. Функции ИИ (LLM)

- Раздел «Настройки» (только для администратора) позволяет без перезапуска сервера:
  задать тон и стиль генерируемых сообщений (системную инструкцию), включить/выключить
  каждый вид автоматических напоминаний по отдельности, задать время ежедневной проверки
  и запустить проверку вручную (для приёмочного контроля, п. 8.1 ТЗ).
- Полное отключение ИИ и выбор поставщика — только через `config/config.json`
  (`llm.enabled`, `llm.activeProvider`), т.к. это влияет на то, какие данные и куда
  уходят за пределы сервера (п. 5.6.5 ТЗ).
- При недоступности LLM-провайдера либо превышении тайм-аута сообщения формируются из
  встроенных шаблонов автоматически — работа прочих подсистем не нарушается.
- Журнал обращений к LLM (дата, тип запроса, инициатор, поставщик, результат) доступен
  в разделе «Настройки» — «Журнал обращений к LLM».

## 8. Приёмочный контрольный сценарий (п. 8.1–8.2 ТЗ)

1. Создать сотрудника (раздел «Сотрудники»).
2. Поставить задачу с сроком и исполнителем (раздел «Задачи»).
3. Обменяться сообщениями — личным и в общем чате (раздел «Чат»).
4. Загрузить и скачать документ (раздел «Документы»).
5. В разделе «Настройки» нажать «Запустить проверку сейчас» и убедиться, что:
   - при наличии сотрудника с днём рождения сегодня в общий чат приходит поздравление;
   - по задачам с приближающимся/просроченным сроком исполнителю приходит напоминание
     (отображается в чате во вкладке «Уведомления»);
   - задачи с истёкшим сроком автоматически переходят в статус «Просрочена».
6. Проверить п. 8.2: временно указать в `config/config.json` заведомо недоступный адрес
   провайдера (или `llm.activeProvider: "template"`) и убедиться, что сообщения всё равно
   формируются — из шаблона, без ошибки в интерфейсе.
